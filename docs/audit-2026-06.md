  Deferred per todo.md M4, but spec/PRD frame it as a v1 guarantee. **The encoder's own KDoc admits this.**
- **`BootReceiver`** (spec §3.1: "restarts the bubble/service after reboot"). No `BootReceiver` exists;

- **History schema** (spec §4.3 lists `durationMs`, `charCount`, `status`, `provider`). Actual table has

- **History retention** — spec §4.3 says "No time-based expiry in v1", but code implements time-based
  retention (`HistoryRepository.kt`). Contradicts spec §4.3, **matches** prd/todo M9 — an internal doc
  conflict; code follows PRD. (This is the M9 work from the current session.)

**prd.md** — P0-5 sensitive-field (see drift below); FLAC not met; P0-8 permission-revocation recovery
not built (M11); injection now inserts-at-cursor, which matches PRD P0-4 but contradicts todo.md.

**testing_plan.md** — §3 "Browser-safety rule" matrix rows (Chrome address bar / web field marked

**README.md** — "AudioRecord → 16 kHz mono PCM/WAV" satisfied; shares the FLAC gap only.

### Sensitive-field drift (verified by hand — narrower than first reported)
`SensitiveFieldClassifier` was changed from a **blanket "any browser text field is sensitive"** rule to
**positive-signal-only**: `isPassword` OR a password input-type, **including** `TYPE_TEXT_VARIATION_WEB_PASSWORD`
(`:45`). So Chrome's `<input type=password>` **is** still refused *when Chrome reports the web-password
variation*. The residual risk is a site that strips the password variation (plain `TYPE_CLASS_TEXT`,
`isPassword=false`) — that field is now dictatable, mitigated downstream by clipboard-fallback (never
written into the wrong field). **The drift is doc-vs-code:** todo.md M3 and testing_plan.md §3 declare the
blanket rule "closed (by request)"; the working tree reverts it. The three modified accessibility test
files in `git status` (SensitiveFieldClassifierTest, InsertionComposerTest, HintNodeInjectionTest) are the
matching **uncommitted** edits. _Not "fixed" here — re-adding the blanket rule is a behavior change, which
this task explicitly forbids; flagged for the owner to reconcile docs vs intended behavior._

### todo.md checkbox drift
- **M3 "Web-password safety rule (closed)"** — contradicted by the working tree (blanket browser branch
  removed). Docs say closed; code rolled it back (uncommitted).
- **M3 "v1 REPLACES the whole field"** — code no longer does this; `InsertionComposer.composeForInjection`
  preserves content and splices at the caret when `selectionEnd > 0` (`InsertionComposer.kt:44-67`). The
  P1 "restore insert-at-cursor" note is effectively already shipped. Docs and the modified
  `InsertionComposerTest` need reconciling.
- **Minor wiring drift:** `SettingsRepository.sessionCapSeconds` (default 300) is **never read** by
  `OverlayService.startRecording` — it calls `audioRecorder.start(...)` without `capMs`, so the hardcoded
  `RecordingLimits.DEFAULT_CAP_MS` applies. Same value, so the cap holds, but the user-facing setting is inert.
- No unchecked `[ ]` item found to be secretly complete; M9 implemented & committed; M10–M13 unstarted.

### Part 2 Summary — most serious gaps (ranked)
1. **Sensitive-field doc/code drift** (privacy + Play risk). Reverts a rule both todo.md M3 and

2. **FLAC-in-v1 not implemented** (spec §1/§2.2/§9). WAV passthrough; breaks the stated upload guarantee.
3. **Injection behavior doc/code disagreement** — code inserts-at-caret; todo.md says replace-whole-field.

- `copy/CopyRepositoryTest.kt` (+4) — format-args on real catalog keys; **every** COMPLIANCE key is lock-proof against `applyOverride`; overridable key applies then reverts when absent from the next bundle; unknown key ignored.
- `stt/RomanizePromptTest.kt` (+1) — blank / regional `en-US` get no prompt (only exact `en`).
